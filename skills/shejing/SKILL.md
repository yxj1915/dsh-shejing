# 摄鲸（shejing）

**从拍摄到整理到后期的一条流水线。** 设计目标只有一个：让每一次失误都变成下一次的规则，
而不是变成下一次的返工。

它不是 Lightroom 工具集——碰 Lightroom 的动作**一律通过 `mcp__lightroom__*` 工具**完成。
摄鲸只负责流程：体检、决策、账本、复盘。

> 这份流程不是凭空写的，是从真实批次里长出来的：一次 75 张 ARW 的拍摄中，28 张连拍重复
> 帧因为「先调色后剔除」而白调了一遍；另一次因为跳过了单张先行门禁，25 张照片整批染成
> 紫红。下面每条规则背后都有一次实际的失败。

---

## 0. 开工前

调 **`shejing_doctor`**。它会报告：Lightroom 增效工具是否已同步、授权 token 是否存在、
桥接端口是否在监听、插件私有目录在哪。

若端口不通，顺序是：Lightroom 里 **文件 ▸ 增效工具管理器 ▸ Lightroom MCP ▸ Start Server**
→ Reload Plug-in → 重启 Lightroom。

**不要猜。先跑 doctor。**

---

## 1. 七个阶段

| 触发词 | 调什么工具 | 门禁 |
|---|---|---|
| **体检** | `shejing_checkup` | —（只读，不碰 Lightroom） |
| **剔除** | `shejing_cull` | 🚪 标记/移动门禁（自动弹出） |
| **整理** | `shejing_organize` | 🚪 不可逆门禁（自动弹出） |
| **调色** | `shejing_grade` | 🚪 新参数门禁（自动弹出） |
| **验收** | `shejing_verify` | — |
| **归档** | `shejing_archive` | 🚪 导出确认（自动弹出） |
| **复盘** | `shejing_retro` | 🚪 写入确认（自动弹出） |

`shejing_batch_status` 读账本，任何时候都可以用来确认进度。

**门禁是机制，不是礼貌。** 带 `confirm: true` 的调用会被 DSH **原生拦下来问用户**，
用户拒绝就真的执行不了。你不需要自己再问一遍——但你需要**在门禁弹出之前**把证据摆好。

**拍摄前规则**不是阶段，是常驻文档：`$DSH_HOME/shejing/shooting-rules.md`，
由「复盘」喂养，只追加、不删除。

---

## 2. 四类门禁 + 固定三段式

停下来时**永远**是这个结构，让用户形成肌肉记忆，也方便他抓到你判断失误的地方：

```
① 证据   我看到了什么（带数字，尽量配图）
② 建议   我建议做什么（含具体参数或名单）
③ 等你   你一句话，我继续
```

四类门禁：

1. **新参数门禁** —— 任何新参数组合**首次**应用（最硬的一条，见下方铁律）
2. **标记/移动门禁** —— 任何色标、旗标、文件移动
3. **不可逆门禁** —— 改硬盘文件名、移动文件
4. **堆栈确认** —— 疑似焦点堆栈**单独开一回合**，不与其他组混报

其余机械步骤连贯做完再汇报。

## 3. ⚠️ 铁律：批量前必须单张先行

**任何新参数组合，先只传 1 张给 `shejing_grade` → 渲染 → 用户看过 → 才批量。**

这条是用 25 张紫色照片换来的。当时一个风格的曲线起点从 `x=0` 挪到 `x=1`
（为了避开工具自动补 `(0,0)` 造成的重复点），没有单张验证就直接上了 25 张——
`(0,0)→(1,8)` 这段近乎垂直，让 Lightroom 的样条在红/蓝通道上严重发散，
整批染上浓重的紫红色偏。诊断、隔离、回滚花了十几轮。

**不要因为「看着只是个小改动」就跳过它。**
**也不要试图找越权参数——没有。**

三种内置风格（`shejing_grade` 的 `style` 参数）：

| | 用途 |
|---|---|
| `A` 暖调电影感 | 城市 / 建筑 |
| `B` 清透日系 | 云彩天空 / 正午 |
| `C` 浓郁黄昏 | 落日 / 篝火 / 剪影 |

风格 B 的曲线原表首点是 `[0,8]`，会触发点曲线端点陷阱；插件已自动归零为 `(0,0)`，
并在结果里说明改了什么。**看到这类说明要转告用户**，不要吞掉。

---

## 4. 非连拍帧的保护

| 类型 | 判据 | 处置 |
|---|---|---|
| 连拍 | 时间邻近 + 构图近似 + **组内曝光跨度 < 0.8 档** | 可进剔除建议 |
| 包围曝光 | 同前，但曝光跨度 **≥0.8 档且成阶梯** | **一律全留**，只报告 |
| 焦点堆栈 | 同秒 + 同构图 + **同曝光**（曝光闸门无效） | **单独确认**，绝不自动剔 |
| 全景 | 构图持续位移，感知哈希自然不同 | 低风险，全留 |

曝光跨度由体检从**照片内嵌 EXIF** 直接算出（不依赖 Spotlight，所以外置盘、网络盘、
刚拷贝的文件都能正常工作）。

**焦点堆栈无法自动判定**——它和连拍的区别只在「清晰位置会逐张移动」，全局锐度指标
看不出来。所以只标记、只确认，不自动剔。

## 5. 账本与目录

```
$DSH_HOME/shejing/
  batches/<批次>/manifest.json     机器账本（各阶段状态）
  batches/<批次>/SUMMARY.md        人读摘要
  batches/<批次>/contact_sheet.jpg
  batches/<批次>/_cache/           每张的缩略图
  batches/<批次>/精选_<时间>/      导出的 JPEG
  batches/<批次>/export-plan.json  精选计划
  shooting-rules.md                拍摄前规则（复盘喂养）
  gates/approved-params.json       已验证参数的白名单
  lrplugin-sync.json               Lua 插件同步记录
  backups/lrplugin-<时间>/         被覆盖的旧 Lua 文件备份
```

**批次定义沿用用户的习惯**——片子在哪个文件夹，那个文件夹就是一批（`9.25`、`1224`、
`未命名文件夹 2` 都行）。摄鲸不要求他改目录习惯，批次身份由 manifest 记录。

---

## 6. 导出规格

原尺寸 · sRGB · JPEG 质量 100 · 保留 EXIF
→ `batches/<批次>/精选_<处理时间>/`

精选 = **星级 ≥4**（阈值可调）自动出候选 → 把清单和缩略图给用户 → 他增删 → 才导。

⚠️ 桥接的 `export_photos` 只暴露 格式/质量/尺寸/目标/同名策略，**没有色彩空间开关**。
色彩空间取 Lightroom 导出默认（JPEG 通常为 sRGB），EXIF 默认保留。

---

## 7. 工作原则

- **事实归我，判断归用户。** 枚举、测量、批量机械操作、交叉核对是工具的事；
  「像不像真的」「留哪个瞬间」「算不算废片」是他的事。把候选渲染成图给他看。
- **不可逆动作归他。** 删原片、删目录记录——最多做标记或移动。
- **只标记不删。** `非导入/` 永久保留，删除动作只能用户来做。
- **不要只信返回值。** `ok`/`success` 可能是假的。关键改动一律用独立手段复核：
  `mcp__lightroom__get_develop_settings` 读回、`read_image` 看图、或 `shejing_verify`
  查目录数据库副本。
- **疑点记进文档，不靠记忆。** 环境的坑写进 `docs/lightroom-classic/gotchas.md`
  （插件包内），流程规则用 `shejing_retro` 写进拍摄前规则。
